# 도메인 규칙

조직별 재무 엑셀 제출, Gap 검토, 소명, 버전, master에 관한 업무 규칙입니다. 화면·API·DB는 이 규칙을 기준으로 구현합니다.

## 1. 용어

| 용어 | 뜻 |
| --- | --- |
| 경영기획 담당자 | 제출을 요청하고, Gap을 검토하고, 승인하는 본사 담당자 |
| 조직 담당자 | 각 조직의 엑셀을 제출하고 소명·변경 사유를 작성하는 담당자 |
| 연간 계획 | 연초에 조직이 제출해 확정한 월별 계획 값 |
| 실적 | 매달 조직이 제출하는 해당 월의 실제 값 |
| 추정치 | 실적 제출 시 함께 받는 다음 달 예상 값. **Gap 대상이 아님** |
| 손익 | 항목별 매출 − 비용 |
| Gap | 같은 조직·항목·월의 **실적 손익 − 계획 손익** |
| Gap 소명 | 경영기획 담당자가 Gap에 대해 요청하는 설명 |
| 변경 사유 | 이미 제출한 값을 바꿀 때 제출 시점에 필수로 적는 설명 |
| 제출본 | 조직이 업로드한 엑셀 한 건. 버전 번호를 가짐 |
| master | 한 달의 모든 조직 승인본을 합친 전사 최종 정답표 |
| Contingency | 승인된 조직 계획 합산 후, 경영기획팀이 전사 단위로 떼어두는 예비분 |
| 보고 영업이익 | 합산 영업이익 − Contingency. 원본 답안지의 "Contingency 제외 영업이익"과 같은 값으로, 연초 보고 기준 |

> 파서 코드의 `gap_relationships`(영업이익·Contingency 관계)는 이 문서의 Gap과 다른 개념입니다.

## 2. 전체 흐름

1. **연간 계획 수집:** 경영기획 담당자가 요청 → 조직이 업로드 → 승인 또는 재제출 요청 → 승인 시 연간 계획으로 확정 → 전사 합산 후 경영기획 담당자가 Contingency 입력
2. **월 실적 수집:** 경영기획 담당자가 요청 → 조직이 업로드 (실적 + 다음 달 추정치)
3. **Gap 검토:** 기준을 넘는 Gap 목록 확인 → 항목별로 확인(인정) 또는 Gap 소명 요청
4. **Gap 소명:** 조직이 소명 작성 → 적절하면 확정, 아니면 재요청
5. **승인:** 모든 Gap이 확인·확정되면 제출본 승인 (조직별 현황에 아카이브)
6. **master 생성·갱신:** 해당 월의 조직 승인본이 모이면 master 생성, 이후 승인으로 값이 바뀌면 새 master 버전 생성 → 홈 화면에 반영
7. **보고:** 표·차트 생성

## 3. 제출과 버전

### 제출 요청

- 연간 계획과 월 실적 모두 **경영기획 담당자의 요청으로 시작**합니다. 조직이 먼저 제출할 수 없습니다.
- 요청이 대상 기간(예: 2026년 연간 계획, 2026년 3월 실적)을 정합니다. 조직은 열린 요청에 대해서만 업로드합니다.
- 업로드는 **열린 요청이 있고, 검토 대기 제출본이 없을 때만** 가능합니다.

### 버전 번호

조직별로 `YYYY-MM-NN` 형식을 씁니다. 백엔드가 업로드 시점에 부여하며, 파일 안에 적지 않습니다.

```
2025-01-01   1월 첫 제출
2025-01-02   1월 재제출
2025-02-01   2월 첫 제출
```

- `YYYY-MM`: 제출 대상 월
- `NN`: 해당 월의 제출 회차. 재제출할 때마다 1씩 증가
- 버전은 **제출할 때만** 올라갑니다. Gap 소명이나 승인으로는 바뀌지 않습니다.

### 제출 상태

| 상태 | 뜻 | 다음 제출 가능 |
| --- | --- | --- |
| 검토 대기 | 업로드 완료, Gap 검토·소명 진행 중 | 불가 |
| 재제출 요청 | 경영기획 담당자가 반려 | 가능 |
| 승인 | 검토 완료, 아카이브됨 | 가능 |

- 조직당 **검토 대기 제출본은 최대 1개**입니다. 승인되거나 재제출 요청을 받기 전에는 다음 버전을 업로드할 수 없습니다.

## 4. 변경 사유

이미 제출한 값이 바뀌면, **제출 시점에 변경 사유를 반드시 입력**해야 제출이 완료됩니다. 변경 사유가 있는 제출본은 경영기획 담당자에게 전달됩니다.

- **비교 기준:** 해당 조직의 **마지막 승인본**의 값
- **비교 범위:** 업로드 파일에 들어 있는 모든 월
  - 같은 달 재제출: `2025-01-02`의 1월 값 vs 1월 마지막 승인본
  - 과거 달 변경: `2025-03-01` 파일 속 2월 값 vs 2월 마지막 승인본
- **표시:** 바뀐 항목마다 `월 · 항목 · 이전 값 → 새 값`을 보여주고 항목별로 사유를 받습니다.
  - 예) `2월 광고비 1,200 → 1,350`
- 비교할 승인본이 없는 월(첫 제출)은 변경 사유 대상이 아닙니다.

## 5. Gap

### 계산

- **단위:** 조직 × 항목 × 월
- **값:** 항목별 손익(매출 − 비용)
- **비교:** 같은 달의 계획과 실적만 비교합니다. 누적 비교는 하지 않습니다.

```
Gap   = 실적 손익 − 계획 손익
Gap률 = Gap ÷ |계획 손익| × 100
```

### 표시 기준

- % 기준과 금액 기준을 **모두** 넘는 항목만 Gap 목록에 표시합니다.
  - 예) 기준 ±5%, 1천만 원 → |Gap률| ≥ 5% **그리고** |Gap| ≥ 1천만 원
- 기준값은 경영기획 담당자가 대시보드에서 설정합니다.

### 기준 설정 UI

- % 기준과 금액 기준을 각각 **슬라이더 + 숫자 입력**으로 조정합니다. 금액 슬라이더는 로그 눈금(100만·1천만·1억 …)을 씁니다.
- 드래그하는 동안 `기준 초과 N건 (조직 M곳)`과 Gap 목록을 **실시간 미리보기**로 갱신합니다.
- 미리보기는 저장되지 않으며, **적용**을 눌러야 기준값이 저장되고 다른 담당자 화면에도 반영됩니다.
- 기준을 바꿔 목록에서 빠지더라도, 이미 Gap 소명을 요청한 항목은 진행 상태를 유지합니다.
- **계획이 0인 경우:** 실적이 0이 아니면 기준과 관계없이 표시합니다. Gap률 대신 "계획 없음"으로 표시합니다.
- 추정치는 Gap을 계산하지 않습니다.

### 검토

| 판단 | 처리 |
| --- | --- |
| 산출 근거가 명확함 | 확인(인정) |
| 산출 근거가 불명확함 | Gap 소명 요청 → 조직이 소명 작성 → 적절하면 확정, 아니면 재요청 |

- 확정된 Gap 소명은 Gap 화면의 소명 모음과 조직별 현황(해당 버전 옆)에 남습니다.

## 6. Contingency

- 연간 계획을 확정할 때 경영기획 담당자가 **전사 단위로 한 번** 입력합니다. 조직별로 배분하지 않습니다.
- 입력 후 연간 계획과 함께 잠기며, 연중에 수정하지 않습니다. 연간 계획 자체도 확정 후 연중 수정하지 않습니다.
- 조직별 Gap은 조직 계획과 조직 실적의 비교이므로 Contingency와 무관합니다.
- 홈 화면과 보고서는 `합산 영업이익 / Contingency / 보고 영업이익`을 함께 보여줍니다.
- 원본 답안지의 "Contingency 제외 영업이익"은 보고 영업이익(합산 − Contingency)입니다. 파서는 이 항목을 `OP_EX_CONTINGENCY`로 식별합니다.

## 7. master

- **최초 생성:** 해당 월의 **모든 조직 제출본이 승인되어야** 첫 master를 생성합니다. 한 조직이라도 미제출·검토 대기·재제출 요청 상태면 생성하지 않습니다.
  - 생성 전에는 홈 화면에 해당 월을 `master 미생성 (승인 N/M 조직)`으로 표시하고, 미승인 조직 목록을 보여줍니다.
- **버전:** 조직 제출본과 같은 `master-YYYY-MM-NN` 형식을 씁니다.

  ```
  master-2025-01-01   1월 첫 master
  master-2025-01-02   1월 값이 바뀐 승인본 반영
  ```

- **갱신:** 조직 제출본이 **승인될 때** 그 제출본이 값을 바꾼 월의 master를 새 버전으로 생성합니다.
  - 같은 달 재제출이 승인되면 그 달의 master를 갱신합니다.
  - 과거 월 값이 바뀐 제출본(변경 사유 포함)이 승인되면 해당 과거 월의 master도 갱신합니다.
  - 검토 대기·재제출 요청 상태의 제출본은 master에 반영하지 않습니다.
- 이전 master는 덮어쓰지 않고 보존합니다.
- Gap 소명은 실적 숫자를 바꾸지 않으므로 master 버전에 영향을 주지 않습니다.
- 홈 화면(전사 손익 현황)은 각 월의 최신 master를 보여주고, 연·월 필터로 이전 master를 볼 수 있습니다.
- 보고서에는 생성에 사용한 master 버전을 함께 기록합니다.

## 8. 역할과 권한

시스템 사용자는 두 역할입니다. CFO·경영진 보고는 업무 흐름에는 있지만 시스템 밖에서 이루어지며, 별도 조회자 역할을 두지 않습니다.

| 역할 | 할 수 있는 것 | 볼 수 있는 제출 기록 |
| --- | --- | --- |
| 경영기획 담당자 | 제출 요청, Gap 기준 설정, 확인·소명 요청, 승인·반려, Contingency 입력 | 전체 조직의 제출 기록 |
| 조직 담당자 | 엑셀 업로드, 변경 사유·소명 작성 | 본인 조직의 제출 기록 |

- 경영기획 담당자는 여러 명일 수 있으며, 모두 전체 조직을 봅니다. 담당 조직을 나누지 않습니다.
- 조직 담당자는 다른 조직의 제출 기록을 볼 수 없습니다.

## 9. 알림

이번 범위에서는 **알림 인터페이스만** 개발합니다. 메일·Slack 등 실제 발송 수단은 구현하지 않으며, 이후 인터페이스 구현체만 추가해 연결합니다.

| 이벤트 | 받는 사람 |
| --- | --- |
| 연간 계획·월 실적 제출 요청 | 조직 담당자 |
| 제출 완료 (변경 사유 포함 여부) | 경영기획 담당자 |
| 재제출 요청 | 조직 담당자 |
| Gap 소명 요청·재요청 | 조직 담당자 |
| 소명 작성 완료 | 경영기획 담당자 |
| 제출본 승인 | 조직 담당자 |
| 마감 리마인드 (미제출·미승인) | 조직 담당자 |

- 백엔드는 업무 로직에서 이벤트를 발행하고, 발송은 인터페이스 구현체가 담당합니다.
- 발송 실패가 제출·승인 등 업무 처리를 막지 않습니다.

## 10. 미정 사항

| 항목 | 결정할 내용 |
| --- | --- |
| 로그인 방식 | 아이디·비밀번호, SSO 등 |
| 마감·리마인드 | 제출 마감일, 조직별 D-day·마감 지남 표시, 리마인드 시점 (master 생성이 모든 조직 승인에 달려 있으므로 검토 중) |
| AI 역할 | 소명 적절성 판단 보조, Gap 원인 요약, 보고서 문장 생성 등 |
