# 파서 비교 정답셋의 구성과 검증 범위

검증 기준 확인일: 2026-11-12

## 요약

이번 비교는 `Data/dummy`의 기본 조직 파일 17개와 마스터 파일 1개를 대상으로 한다. 정답은 더미 데이터 생성 당시 작성된 `manifest_baseline.json`의 `expected` 값이다. 셀별 조직·항목·기간을 사람이 검수한 정답셋을 새로 구축한 것은 아니다.

현재 지표는 **재무 집계 금액 일치율**이다. 셀별 의미 정확도, AI의 일반적인 맥락 이해 능력, DB 적재 성공률을 측정한 지표로 해석하면 안 된다.

AI 비교는 대화 모델이 작성한 구조 해석 계획을 기존 AI 파서에서 재생한 방식이다. 실제 외부 모델 API를 호출한 전체 실행 성능 실험은 아니다.

## 1. 정답의 출처와 생성 과정

기준 manifest 버전은 `baseline_strict_native_input_only_v1`이다. 데이터 생성 코드에서 다음 과정을 확인했다.

```text
합성 재무 데이터 원본: baseline_fixture.json
    │
    ├─ Excel 양식에 입력
    │      └─ 조직 파일 17개 + 전체 마스터 1개
    │
    └─ 생성 행의 월별 금액을 직접 합산
           └─ manifest_baseline.json의 expected
                         │
                         └─ 파서 출력의 정규화 금액 합계와 비교
```

- `original_data()`는 기존 합성 데이터인 `baseline_fixture.json`을 읽는다.
- `expected_data(rows)`는 생성에 사용하는 행별 월 금액을 직접 합산해 월별·연간 기준 합계를 만든다.
- `check_values()`는 저장된 XLSX 내부의 숫자 셀을 읽고 생성 데이터의 월별 값 및 연간 합계와 비교한다.
- 룰베이스 또는 AI 파서의 출력을 정답으로 사용하지 않는다. manifest는 평가에 사용하며 파서 입력이나 AI 계획 작성용 정답으로 제공하지 않았다.

따라서 기준값은 **비교 대상 파서의 출력과 독립적으로 계산된 기대 합계**다. 다만 입력 Excel과 정답 합계가 같은 합성 데이터를 원천으로 사용하므로, 입력 생성 과정과도 독립적인 사람 검수 정답은 아니다.

## 2. 정답의 구성

| 항목 | 내용 |
|---|---|
| 파일 식별 정보 | 파일명, 조직 코드·이름, 마스터 여부 |
| 조직 파일 상세 행 수 | 매출 35행, 비용 24행 |
| 마스터 상세 행 수 | 매출 595행, 비용 408행 |
| 매출 기준 합계 | 4개 기간 영역 × (12개월 + 연간) = 52개 |
| 비용 기준 합계 | 5개 기간 영역 × (12개월 + 연간) = 65개 |
| 기준 금액 단위 | 천원. 평가 시 원으로 1,000배 변환 |

매출·비용의 공통 기간 키는 `prior`, `plan`, `outlook`, `next_plan`이다. 비용에는 `next_projection`이 추가된다. `outlook`은 기본 데이터의 2026년 실적·추정 영역이며, 이 기간 키가 존재한다는 사실만으로 파서의 월별 실적/추정 분류까지 채점되는 것은 아니다.

파일당 평가 그룹은 117개다. 조직 17개는 총 1,989개 그룹, 마스터는 별도 117개 그룹으로 평가한다. 마스터는 조직 데이터를 합친 파일이므로 독립적인 추가 표본으로 간주하지 않는다.

## 3. 평가 범위와 통과 조건

평가기는 더미 생성 계약에 정해진 시트·좌표와 manifest의 상세 행 수로 필요한 셀을 결정한다. **파서가 예측한 조직이나 기간 라벨로 합산 대상을 선택하지 않는다.**

| 구분 | 시트 | 상세 시작 행 | 각 기간의 연간 열 |
|---|---|---:|---|
| 매출 | `매출_세부_IFRS15後` | 5 | H, V, AJ, AX |
| 비용 | `OpEx_세부_IFRS15後` | 6 | Q, AE, AS, BG, BU |

각 연간 열의 다음 12개 열이 해당 기간의 월별 평가 대상이다. 마지막 행은 시작 행과 manifest의 `records`로 계산한다. 마스터 매출도 전체 595행을 포함하며, 뒤쪽 상세 행을 포함하지 않는 원본 상단 `SUBTOTAL`을 정답으로 사용하지 않는다.

한 그룹이 통과하려면 다음 조건을 모두 만족해야 한다.

1. 필요한 원본 셀마다 출력 레코드가 정확히 하나 존재한다.
2. 각 레코드의 `value.status`가 `confirmed`이고 `value.value_kind`가 `amount`다.
3. `value.normalized_value`가 유한한 숫자로 해석된다.
4. 정규화 금액을 `Decimal`로 합산한 값이 원 단위 기준 합계와 정확히 같다. 오차 허용값은 없다.

누락·중복·미확정 셀이 있는 그룹은 실패로 계산하며 분모에서 빼지 않는다.

```text
금액 집계 일치율 = 모든 조건을 통과한 그룹 수 / 전체 평가 그룹 수
```

`mapping.status`는 별도로 집계한다. 이 상태가 `partial` 또는 `unmapped`이더라도 위 금액 조건을 만족하면 합계 채점은 통과할 수 있다.

## 4. 실제 채점 예시

```text
파일: 01_F10_사업부1_재무제표.xlsx
시트: 매출_세부_IFRS15後
대상: I5:I39 — 이전 연도 1월 매출, 35개 셀

manifest 경로: expected.revenue.periods.prior.monthly[0]
기준값: 579,220천원
원 단위 정답: 579,220,000원

파서 출력의 해당 35개 셀이 모두 금액으로 확정되고,
정규화 금액 합계가 579,220,000원이면 이 그룹은 통과한다.
```

이 정답은 `I5` 한 셀의 값이 아니라 **I5부터 I39까지의 합계**다. 각 셀의 개별 금액이나 의미 필드가 정답과 일치하는지를 모두 검사한 결과는 아니다.

## 5. 검증한 것과 검증하지 않은 것

| 항목 | 이번 금액 합계 채점에서 검증 여부 |
|---|---|
| 평가 대상 셀의 출력 누락·중복 | 검증 |
| 평가 대상 셀의 금액 확정 여부 | 검증 |
| 월별·연간 그룹의 정규화 금액 합계 | 검증 |
| 개별 셀 금액의 정답 일치 | 별도 채점하지 않음 |
| 조직·항목·연도·월·실적/계획/추정의 정확성 | 별도 셀별 정답이 없어 미측정 |
| 단위 라벨 자체의 정확성 | 별도 채점하지 않음. 정규화 합계에는 반영됨 |
| 수식 결과의 최신성 | Excel 재계산으로 검증하지 않음 |
| DB 저장·중복 방지·조회 정확성 | 미검증 |

원본 파일 해시, 원본 XML 대비 추출 결과, 출력의 출처 연결은 별도의 검증이다. 이 검증들이 통과해도 업무 의미가 정확하다는 뜻은 아니다. 이번 실행에서는 양쪽 파서 모두 `예산코드!A178`의 `COMMENT_MISMATCH`가 남아 원본 추출 검증 전체를 통과하지 못했다.

현재 합계 정답만으로는 다음 오류를 놓칠 수 있다.

- 한 셀의 과대 금액과 다른 셀의 과소 금액이 상쇄되는 경우
- 금액은 맞지만 조직·항목·기간·시나리오를 잘못 연결한 경우
- 합계 평가 범위 밖의 셀을 잘못 해석한 경우
- 합성 데이터 생성 단계의 업무 의미 오류가 입력과 정답에 함께 반영된 경우

앞서 보고한 조직 파일의 룰베이스 55.6%, AI 계획 재생 44.4%, 마스터의 룰베이스 55.6%, AI 계획 재생 100%는 모두 이 범위의 **금액 집계 일치율**이다. 특히 마스터 100%가 모든 의미 필드의 정확성을 뜻하지 않는다.

## 6. 셀별 의미 검증을 위한 추가 정답셋

다음은 현재 완료된 검증이 아니라 후속 구성 항목이다.

셀별 정답은 `파일명 + 시트명 + 셀 주소`를 키로 하여 조직 코드, 항목 코드·이름, 연도, 월, 집계 구분, 실적/계획/추정, 원본 단위, 원 단위 금액을 확정해야 한다. 모호한 헤더, 미확정 값, 제외 대상에 대한 기대 상태와 판단 근거도 함께 관리해야 한다.

이 정답을 파서 출력과 분리하여 검수한 뒤 비교해야 셀별 의미 정확도를 보고할 수 있다. 비교 환경에는 별도 `--truth` 평가 경로가 있지만 이번 실행에는 셀별 정답을 제공하지 않았으며, 의미 정확도는 `null` / `not_scored`다.

## 근거 파일

아래는 확인에 사용한 경로다. `Data/`는 이 Git 저장소의 형제 디렉터리에 있는 로컬 데이터이며, 이 문서에 데이터 원본이나 생성 코드를 복사하지 않는다. 비교 구현 경로는 검증 당시 작업 폴더 기준이다.

- `../Data/dummy/manifest_baseline.json`: 기존 기준 합계와 생성 검증 기록
- `../Data/.dummy_build/strict_v3/baseline_fixture.json`: 합성 데이터 원본
- `../Data/.dummy_build/strict_v3/build_baseline.py`: `expected_data()`, `check_values()` 및 생성 흐름
- `../Data/dummy/원본양식_설명.txt`: 단위·기간·마스터와 원본 수식의 제약
- `parser/src/excel_parser/benchmark/manifest.py`: 117개 그룹의 금액 채점
- `parser/src/excel_parser/benchmark/evaluation.py`: 별도 셀별 정답 평가

이 문서는 정답셋의 구성과 검증 범위를 기록한다. 정답셋 추가 생성이나 파서 로직 변경은 포함하지 않는다.
