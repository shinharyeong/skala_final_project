# 원본 근거와 의미 매핑 규칙

## 범위와 구현

구현은 `src/excel_parser/mapping.py`의 `map_workbook(workbook, metadata=None)`입니다. `extraction.extract_workbook`의 메모리 결과를 받아 표준 레코드, 진단, 집계, GAP 지표 관계를 반환합니다. 이 모듈은 파일 읽기·쓰기, 수식 계산, DB 저장을 수행하지 않습니다.

전체 원본 보존과 재무 의미 매핑은 다른 단계입니다. 파일·조직·시트 개수는 입력에서 읽으며 고정 전제로 사용하지 않습니다. 이 문서는 파서 규칙과 검증 방법만 설명하며, 실제 입력 파일명·조직 식별자·셀 위치·원본 값·특정 실행의 조사 결과는 포함하지 않습니다.

## 지원하는 표 구조

시트 이름만으로 표를 판정하지 않습니다. 다음 원본 헤더 조합을 확인해야 해당 규칙을 적용합니다. 헤더 위치와 연도·월은 값에서 읽습니다.

| 원본 구조 | 식별 근거 | 의미와 주의점 |
| --- | --- | --- |
| 매출 상세 | `조직명`, `관리분류`, `중분류`, `소분류`, `사업부코드`; 연도/시나리오 헤더와 월·연간 헤더 | 원본 조직 행과 상세 분류·거래내역 차원을 보존. 헤더 위치는 입력에서 확인 |
| OpEx 상세 | `대분류`, `중분류`, `소분류`, `조직명`, `예산Code`; 연도/시나리오 헤더와 월·연간 헤더 | 예산코드, 팀, 실행과제, 비용구분, 실적집계기준, 거래내역을 각각 보존. 헤더 위치는 입력에서 확인 |
| 재무 답안지 | 연도·계획/실적/추정·분기/연간·월의 다단 헤더 | 왼쪽 항목 열의 들여쓰기를 항목 경로로 읽음. 표준값은 합계·소계로 분류하며 상세와 중복 합산하지 않음 |
| 사업부별 집계 | 사업부코드·사업부명과 `<연도> <시나리오> <항목>` 형태의 복합 헤더 | 조직별 연간 요약. 전체 합계 행도 보존하며 조직 행과 구분 |
| 코드표·참고 시트 | 위 재무 구조에 해당하지 않는 표 | 원본은 모두 보존. 숫자나 수식 후보도 표준 목록에 남기되 재무 의미 미확정으로 구분 |

단위·기간·시나리오 설명이 있는 경우 표 자체의 헤더·수식과 대조합니다. 설명의 위치를 고정된 셀 주소로 가정하지 않습니다. 통합 파일의 집계 범위나 내부거래 제거 여부도 명시된 근거 없이 추정하지 않습니다.

## 적용 규칙

| 규칙 ID | 내용과 근거 |
| --- | --- |
| `MAP_REVENUE_DETAIL` | 매출 상세 헤더를 확인하고 행의 조직코드·조직명, 관리·중·소분류와 값 열을 연결 |
| `MAP_EXPENSE_DETAIL` | OpEx 상세 헤더를 확인하고 예산코드·항목명·추가 차원과 값 열을 연결. 숫자 예산코드와 조직명 수식 캐시는 금액으로 변환하지 않음 |
| `MAP_FINANCIAL_STATEMENT` | 답안지의 항목 계층과 다단 기간 헤더를 연결. 월 값과 연간 값을 구분 |
| `MAP_ORGANIZATION_SUMMARY` | 복합 헤더의 연도·시나리오·항목과 행의 조직을 연결 |
| `MAP_UNKNOWN` | 지원 표 구조를 확인하지 못한 후보. 값·수식과 출처를 보존하고 재무 의미를 확정하지 않음 |
| `PERIOD_CROSS_SHEET_MONTH_SCENARIO` | 상세의 실적/추정 혼합 헤더를 같은 워크북 답안지의 동일 연월에 명시된 시나리오로 보완. 전환 월을 고정하지 않음 |
| `PERIOD_ANNUAL_MIXED_COMPONENTS` | 연간 헤더의 시나리오와 연결 월별 값의 시나리오를 대조. 실적·추정이 함께 있으면 연간은 `mixed`로 표시하고 원본 헤더는 그대로 보존 |
| `UNIT_SUBTOTAL_THOUSAND_TO_HUNDRED_MILLION` | 상세 상단 `SUBTOTAL(...)/100000`은 천원 상세를 억원으로 환산한 결과. 상세 제목의 천원 단위를 다시 적용하지 않음 |
| `UNIT_SUBTOTAL_CONVERSION_UNRESOLVED` | 상세 상단 소계의 단위 변환이 지원된 수식 근거와 다르면 단위를 미확정으로 남김 |
| `FORMULA_CACHE_UNAVAILABLE` | 캐시 누락·오류 수식은 원문과 출처를 남기며 값을 0으로 대체하지 않음 |
| `GAP_PREFER_EXPLICIT_NO_AUTOMATIC_ADJUSTMENT` | 명시된 Contingency 제외 영업이익이 있으면 그 원본 레코드를 우선 연결. 추가 조정값을 계산하지 않음 |

병합 헤더는 기준 셀 주소와 상속 대상 행·열·병합 범위를 `period.provenance[].inheritance`에 기록합니다. 헤더 해석 때문에 원본 빈 셀을 생성하거나 금액을 복제하지 않습니다.

## 출처·항목·정규화

- 모든 표준 레코드의 `source.raw_record_id`는 추출된 원본 셀을 가리킵니다. 파일 식별자·입력 경로·시트·셀도 함께 제공합니다.
- `raw_value`와 `formula`는 원본 값과 수식/캐시 상태를 그대로 보존합니다. 수식 캐시는 재계산 결과가 아닙니다.
- `item.code`는 원본 예산코드가 있으면 그 문자열을 사용합니다. 원본 항목코드가 없으면 임의 발급하지 않습니다. 영업이익 등 확인된 지표에는 아래 지표 코드가 들어갈 수 있습니다.
- `item.metric_code`는 GAP 지표 식별용 `OP`, `CONTINGENCY`, `OP_EX_CONTINGENCY` 또는 null입니다. 원본 예산코드와 별개로 유지합니다. 영업이익률을 영업이익 금액으로 분류하지 않습니다.
- 항목 계층은 `item.header_path`, 실제 구분 차원은 `dimensions`에 근거 셀과 함께 남깁니다. 동일 항목명이더라도 차원이 다르면 같은 레코드로 합치지 않습니다.
- 정상 숫자의 내부형은 `Decimal`입니다. `value.normalized_value`와 `value.multiplier`는 저장 계층에서 십진 문자열로 직렬화해야 합니다. 숫자 서식과 스타일은 `style_reference` 및 원본 스타일 자료를 참조하며 반복적인 표시 형식 해석 전체를 각 레코드에 복제하지 않습니다.
- 금액은 명시된 원·천원·백만원·억원을 원 기준으로 정규화합니다. 비율은 원본 숫자에 백분율 배율을 다시 적용하지 않습니다. 원본 값·원본 단위·적용 배율은 별도 필드로 남습니다.

## 조직·제출 정보와 집계 제한

조직은 실제 상세 행의 코드·원래 이름에서 읽습니다. 같은 워크북의 조직 코드표만 보조 근거로 사용합니다. 여러 조직 상세와 조직별 집계 구조가 함께 있는 파일은 `source.workbook_role=consolidated_reference`, 단일 조직 상세 파일은 `organization_workbook`으로 표시합니다. 이는 승인 완료나 공식 마스터 지위를 뜻하지 않습니다. 통합 파일에서 조직 파일의 숫자를 가져오지 않습니다.

`metadata`는 `organization_code`, `organization_name`, `submission_month`, `submission_version`, `submission_cycle`, `revision`, `locale`을 선택적으로 받습니다. 조직 메타데이터는 원본에서 조직을 확인하지 못했을 때 사용합니다. 제출 월은 `YYYY-MM`, 버전은 문자열이어야 합니다. 합성 예시 `V1.01`은 원문을 유지한 채 회차 1·개정번호 1로 분리할 수 있습니다. 버전 문자열을 소수로 저장하지 않습니다. 대상 연월에서 제출 월을 유추하지 않습니다.

상세·소계·합계·비율·참고의 역할과 월·연간 집계 차원을 각각 제공합니다. `role.aggregatable=false`는 현재 계약에서 모든 레코드의 일괄 합계를 허용하지 않는다는 뜻입니다. 조직·제출본·대상 기간·시나리오·단위·항목·추가 차원을 고정하고 상세/합계 중복과 통합 참고 파일 중복을 제거하는 정책은 후속 소비자가 정해야 합니다. 현재 파서는 전사 마스터를 발행하거나 업무 승인 상태를 만들지 않습니다.

## 집계와 미확정 상태

`mapping.status`는 다음 세 상태입니다. 제출 정보의 확인 상태는 별도로 유지합니다.

| 상태 | 의미 |
| --- | --- |
| `mapped` | 값 정규화와 조직 범위·항목·대상 기간·시나리오·필요 단위가 확인됨 |
| `partial` | 재무 값 영역이나 지표를 식별했지만 일부 의미나 정규화가 미확정 |
| `unmapped` | 재무 의미를 확인하지 못한 숫자·수식 후보 또는 비금액 참조 필드 |

원본의 값·수식 셀 수와 표준 재무/숫자·수식 후보 수는 같지 않을 수 있습니다. 제목·설명·문자열 코드 등은 원본 추출에 보존되며, 표준 숫자 목록에 들어가지 않을 수 있습니다. 원본 숫자·수식 후보는 표준 목록에서 제거하지 않습니다.

Contingency 또는 제외 영업이익을 확인할 근거가 없으면 해당 항목과 계산 관계를 미확정으로 남깁니다. 파서는 원본 지표와 수식을 연결하지만, 근거 없이 Contingency 제외 영업이익을 계산하지 않습니다. 숫자 저장 부호·캐시 누락·지원하지 않는 구조 등은 입력별로 진단하며 모든 입력의 의미 해석이 완료된 것으로 보고하지 않습니다.

## 검증

`PYTHONPATH=src python3 -B -m unittest discover -s tests -p test_mapping.py -v`

메모리의 합성 입력과 별도로 관리하는 로컬 fixture로 다음을 검증합니다. fixture 운영 및 실행 범위는 [프로젝트 README](../../README.md)를 따릅니다.

- 원본 후보 연결·원문 값·수식 보존과 병합 헤더의 기준 셀 연결.
- 명시된 단위에 따른 상세·소계 변환. 합성 예시로 `100천원`은 `100000원`이며, 표시 배율을 중복 적용하지 않음.
- 연간·월별 값과 실적·추정 혼합 기간의 구분. 특정 연도나 시나리오 전환 월을 정답으로 하드코딩하지 않음.
- 숫자 코드·텍스트 수식 캐시의 비금액 처리와 캐시 없는 수식의 미확정 상태.
- 제출 정보 미추정, 문자열 버전 보존, 명시된 제외값의 중복 조정 방지.

기대값은 합성 입력에 명시한 상수·수식 또는 독립 원본 점검을 근거로 정합니다. 파서 결과를 그대로 정답으로 재사용하지 않습니다. 원본 파일을 변경하거나 검증용 엑셀을 생성하지 않습니다.

## 함수 역할과 호출 관계

모든 함수의 인자·반환·예외·부작용에 대한 상세 계약은 코드 docstring에 있습니다.

| 함수 | 호출·책임 |
| --- | --- |
| `map_workbook` | 파이프라인 진입점. 아래 헬퍼와 `normalize_number`를 호출 |
| `_text`, `_ref` | 저장값 조회와 원본 근거 참조 생성 |
| `_index`, `_header_at` | 시트 색인 및 병합 헤더의 기준 셀 해석 |
| `_scenario`, `_year`, `_period` | 명시된 헤더의 시나리오·연도·기간 해석 |
| `_layout` | 원본 헤더 조합에 따른 표 구조 식별 |
| `_periods_with_cross_evidence` | 같은 워크북의 명시 월별 시나리오 연결 |
| `_organization_registry`, `_workbook_organization` | 같은 워크북의 코드표와 상세 행에서 조직 범위 확인 |
| `_metric`, `_unit` | 명시 항목명과 단위 설명 해석 |
| `_submission` | 전달받은 제출 메타데이터 검증·보존 |
| `_statement_items`, `_row_context` | 행별 계층·조직·항목·추가 차원·역할 구성 |
| `_gap_relationships` | 원본 지표와 수식의 관계만 연결하고 계산하지 않음 |
