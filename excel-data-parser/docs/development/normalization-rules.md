# 숫자·음수·단위 정규화 규칙

## 범위와 원칙

[normalization.py](../../src/excel_parser/normalization.py)는 저장 숫자와 문자열 숫자를 구분하는 순수 함수 모듈입니다. 파일·DB·콘솔을 사용하지 않습니다. 원본 값은 항상 `original_value`에 남기고, 해석 근거를 `rule_ids`, 미확정 사유를 `diagnostics`에 기록합니다.

이 문서의 숫자·코드·표기 예시는 정규화 동작을 설명하기 위한 **합성값**입니다. 실제 입력 파일명, 조직 식별자, 원본 셀 위치, 원본 금액, 특정 실행의 조사·검증 결과는 포함하지 않습니다.

**원본 자료형과 실제 저장값이 표시보다 우선합니다.** Excel 표시 형식은 셀의 실제 계산값을 바꾸지 않는다는 [Microsoft의 숫자 서식 설명](https://support.microsoft.com/en-us/excel/number-format-codes-in-excel-for-mac)을 기준으로, 저장 숫자에는 빨간색·괄호·삼각형·화살표·0의 대시 표시를 다시 적용하지 않습니다.

내부 계산은 `Decimal`을 사용합니다. XML 숫자 문자열에서 직접 만들고, 단위 배율 곱셈에는 원본 자릿수보다 넉넉한 지역 연산 정밀도를 지정합니다. 기본 연산 정밀도 28자리 때문에 원본이 잘리는 문제를 방지합니다. 이는 이미 원본에 없는 정밀도를 복원한다는 의미가 아닙니다. [Python Decimal 문서](https://docs.python.org/3/library/decimal.html)의 문자열 생성 및 연산 문맥 기준을 따릅니다.

## 인터페이스

```python
normalize_number(
    value,
    *,
    data_type,
    value_kind=None,
    unit=None,
    number_format=None,
    locale=None,
    symbol_rules=None,
)
```

| 입력 | 의미 |
| --- | --- |
| `value` | 원본 저장값 또는 문자열. 숫자 셀은 XML의 숫자 원문 문자열을 전달 |
| `data_type` | `number`, `string`, `boolean`, `error`, `date`, `blank` 등 원본 자료형 |
| `value_kind` | 확인된 `amount`, `ratio`, `quantity`, `number`. `code`, `identifier`, `date`, `text`, `version` 등은 숫자 변환 금지 |
| `unit` | 원본 헤더·제목·수식에서 확인한 값의 단위. 표시 배율과 별개 |
| `number_format` | 원본 표시 형식. 값이나 부호를 재계산하는 데 사용하지 않음 |
| `locale` | 확인된 `ko_KR`, `en_US`, `de_DE`, `fr_FR` 또는 단축 코드. 미지정이면 모호한 표기는 보류 |
| `symbol_rules` | 범례·템플릿으로 확인된 기호별 부호. `{"△": {"sign": -1, "rule_id": "확정된-규칙-ID"}}` 형태 등 |

문자열은 숫자 필드라는 근거가 있을 때만 변환합니다. 조직 코드 `00123`을 문자열 숫자처럼 보인다는 이유로 금액으로 바꾸지 않습니다. 표준 레코드의 전체 확인 상태는 숫자 정규화 상태와 별개이며, 조직·기간·항목이 미확정이면 전체 의미 매핑까지 완료했다고 간주하지 않습니다.

## 반환 및 직렬화 계약

| 필드 | 내부 타입 / 의미 |
| --- | --- |
| `original_value` | 전달된 원본 그대로 |
| `normalized_value` | 확정 시 `Decimal`, 그 외에는 `None` |
| `status` | `confirmed`, `unresolved`, `not_numeric`, `missing` |
| `value_kind` | 확인된 값 종류 또는 원래의 미확정 상태 |
| `currency` | 확인된 통화 코드 또는 `None` |
| `source_unit` | 헤더 또는 문자열에서 확인한 원본 단위 |
| `multiplier` | 정규화에 실제 적용한 `Decimal` 배율 |
| `rule_ids` | 적용한 규칙과 중단 사유의 식별자 목록 |
| `diagnostics` | 코드와 사람이 읽을 설명 |
| `format_analysis` | 원본 서식, 구간·조건·색·백분율 표시·표시 배율 메타데이터 |

JSON/JSONL에서는 `Decimal`을 JSON number나 float로 바꾸지 않고 **십진수 문자열**로 직렬화합니다. 현재 저장 계층은 `format(value, "f")`로 지수 표기 없는 고정 소수점 문자열을 쓰며, 소비자는 문자열을 십진수 타입으로 읽어야 합니다. 원본 숫자 렉심과 자료형은 별도 원본 레코드에서 유지합니다. 파일 쓰기는 이 모듈의 책임이 아닙니다.

`missing`도 빈 문자열·값 없음·명시적 미입력의 규칙 ID를 구분합니다. 문자열 `-`는 `unresolved`, 실제 숫자 `0`은 `confirmed`인 `Decimal("0")`입니다.

## 등록된 규칙

| 규칙 ID | 조건과 처리 | 독립 기대값 예시 |
| --- | --- | --- |
| `RAW-NUMBER-001` | 숫자 저장값을 직접 Decimal로 읽음 | 저장 `-100` → `-100` |
| `RAW-FORMAT-001` | 서식은 보존하고 저장 부호·값에는 미적용 | 저장 `100`, 양수 빨강/괄호 서식 → `100` |
| `RAW-PERCENT-001` | 이미 숫자인 비율에 `%` 배율 중복 적용 금지 | 저장 `0.125`, 단위 `%` → `0.125` |
| `TEXT-CONTEXT-REQUIRED` | 숫자 필드 근거가 없으면 변환하지 않음 | 문자열 `00123`, 종류 미정 → `not_numeric` |
| `TEXT-UNICODE-001` | NFKC와 Unicode 마이너스 정리 | `－１，０００` → `-1000`, 확인된 한국 로케일 |
| `TEXT-SIGN-LEADING` | 숫자 전체의 앞쪽 부호 1개 | `- 1,000` → `-1000` |
| `TEXT-SIGN-TRAILING` | 숫자 전체의 뒤쪽 부호 1개 | `1,000 -` → `-1000` |
| `TEXT-ACCOUNTING-001` | 확인된 금액·비율 필드의 전체 괄호 | `(₩1,000)` → `-1000` |
| `TEXT-SYMBOL-001` | 명시적 기호 규칙이 있을 때만 부호 적용 | 범례에서 음수로 확정한 `△100` → `-100` |
| `TEXT-SYMBOL-UNCONFIRMED` | 범례 없는 삼각형·화살표는 보류 | `▼100` → `unresolved` |
| `TEXT-SIGN-CONFLICT` | 복수의 외부 부호는 곱하지 않음 | `(-100)`, 범례가 있어도 `△-100` → `unresolved` |
| `TEXT-NUMBER-001` | 단위·부호 제거 후 전체 숫자 형태 검증 | `1E-3` → 양수 `0.001` |
| `TEXT-LOCALE-001` | 확인된 로케일로 그룹·소수 구분 | 독일 `1.234,56` → `1234.56` |
| `TEXT-NUMBER-AMBIGUOUS` | 전체 형태 또는 구분자가 모호하면 보류 | 로케일 없는 `1,234`, `1.234`, `--100` |
| `TEXT-PERCENT-001` | 문자열 백분율에만 1/100 적용 | `(12.5%)` → `-0.125` |
| `UNIT-001` | 확인된 원본 단위를 한 번만 환산 | `1.25천원`, 헤더도 천원 → `1250`원 |
| `UNIT-CONFLICT` | 헤더 단위와 문자열 단위가 다르면 보류 | 헤더 백만원, 문자열 `1천원` |
| `TYPE-PROTECTED` | 코드·날짜·불리언·Excel 오류 등 보호 | `A-100`, `True`, `#DIV/0!` 변환 금지 |
| `TYPE-DATE-FORMAT` | 날짜·시간 표시 형식을 금액으로 처리하지 않음 | 날짜 일련번호와 `yyyy-mm-dd` |
| `TEXT-DASH-PLACEHOLDER` | 대시는 실제 0으로 바꾸지 않음 | 문자열 `-` → `unresolved` |

미등록 단위·충돌 통화·비유한 숫자·숫자 중간 기호 등에도 별도 진단 코드를 반환합니다. 이 목록은 범용 숫자 렌더링 엔진이나 모든 문자 기호 지원을 뜻하지 않습니다.

## 단위와 서식 배율

- 금액 단위: 원, 천원, 만원, 백만원, 억원 및 등록된 통화 단위.
- 수량 단위: 명, 천명, 만명, 개, 건, 대.
- 비율: 문자열 `%`·퍼센트는 0.01, 숫자 저장 비율은 이미 값이므로 배율 1.
- `#,##0,,`의 쉼표 두 개는 표시 시 축소하는 정보로만 기록합니다. 실제 저장값을 추가로 1,000,000배 하거나 나누지 않습니다.
- 헤더 단위와 문자열 단위가 같으면 한 번만 적용합니다. 서로 다르면 추측해서 환산하지 않습니다.
- `$`, `¥`만으로 통화를 확정하지 않습니다. 명시적 통화 코드나 단위가 함께 있어야 확정합니다.
- 값 감소는 음수 값 자체와 다릅니다. 합성 예시의 저장값 `100`은 다른 기준값보다 작더라도 양수로 유지합니다. 이전 기준과의 차액 계산은 이 정규화 함수의 책임이 아닙니다.

## 합성 예시와 규칙 연결

아래는 실제 데이터에서 추출하지 않은 독립적인 검증 예시입니다. 원본 자료형, 필드 의미, 확인된 단위를 별도 입력하고 기대값을 직접 정합니다.

| 합성 입력과 조건 | 적용 규칙 | 기대 결과 |
| --- | --- | --- |
| 숫자 저장값 `100`, 확인된 단위 천원 | `RAW-NUMBER-001`, `UNIT-001` | `100000`원 |
| 숫자 저장값 `-100`, 음수 구간에서 부호를 숨기는 서식 | `RAW-NUMBER-001`, `RAW-FORMAT-001` | `-100` 유지 |
| 숫자 저장값 `100`, 빨강 또는 괄호 표시 | `RAW-NUMBER-001`, `RAW-FORMAT-001` | 양수 `100` 유지 |
| 숫자 저장값 `0`, 0 구간의 대시 표시 | `RAW-NUMBER-001`, `RAW-FORMAT-001` | 실제 `0` 유지 |
| 문자열 `100천원`, 확인된 헤더 단위도 천원 | `TEXT-NUMBER-001`, `UNIT-001` | `100000`원, 단위는 한 번만 적용 |
| 비율 문자열 `(12.5%)` | `TEXT-ACCOUNTING-001`, `TEXT-PERCENT-001` | `-0.125` |
| 숫자 저장 비율 `0.125`, 백분율 표시 | `RAW-NUMBER-001`, `RAW-FORMAT-001` | `0.125`, 1/100을 다시 적용하지 않음 |
| 문자열 `△100`, 기호 의미를 확인할 근거 없음 | `TEXT-SYMBOL-UNCONFIRMED` | 원문과 미확정 사유 유지 |

단위 근거는 제목·헤더·명시적 메타데이터 또는 지원되는 수식 관계에서 가져옵니다. 상세 시트 전체에 하나의 단위를 일괄 적용하지 않습니다. 예를 들어 천원 단위 상세를 `/100000`으로 나눈 요약 수식은 억원으로 변환되므로 의미 매핑이 그 근거를 확인하고 별도 단위를 전달해야 합니다.

## 지원 범위와 한계

- 등록된 문자열 숫자 문법·단위·로케일·기호 규칙만 지원합니다. 미등록 표기는 원문과 진단을 보존합니다.
- 표시 형식의 구간·조건·색·표시 배율은 메타데이터이며 Excel 화면을 재현하는 렌더링 결과가 아닙니다.
- 수식은 계산하지 않습니다. 상위 추출 계층이 제공하는 저장 캐시의 존재·오류·확인 상태를 별도로 유지해야 합니다.
- 단위·조직·기간·항목의 업무 의미를 숫자 형태만으로 결정하지 않습니다.
- 실제 데이터에 어떤 표기가 등장했는지는 별도로 관리하는 입력과 실행 결과에서 확인해야 합니다. 합성 테스트 통과가 모든 입력 형식의 지원을 의미하지 않습니다.

## 검증과 함수 명세

실행 명령:

```bash
PYTHONPATH=src python3 -B -m unittest discover -s tests -p 'test_normalization.py' -v
```

[test_normalization.py](../../tests/test_normalization.py)는 부호·통화·단위·고정밀도·날짜·0/대시를 합성 입력과 독립 기대값으로 검증합니다. 원본 파일 전수 추출과 매핑 대조는 별도로 관리하는 로컬 fixture를 사용하는 전체 파이프라인 검증이 담당합니다. fixture 운영 및 실행 범위는 [프로젝트 README](../../README.md)를 따릅니다.

| 함수 | 호출자 / 역할 | 입출력·예외·부작용 |
| --- | --- | --- |
| `normalize_number` | 의미 매핑 / 정규화 공개 진입점 | 원본과 명시적 맥락 → 상태·Decimal 값·근거. 미지원 표기는 진단 반환, 파일 접근 없음 |
| `inspect_number_format` | 정규화·스타일 조사 / 서식 메타데이터 | 서식 문자열 → 구간·조건·색·표시 배율. 렌더링·수식 계산·값 변경 없음 |
| `_base_result` | 정규화 / 결과 객체 초기화 | 입력 → 독립된 결과 사전. 원본 변경 없음 |
| `_stop` | 정규화 / 미확정·비숫자·빈 값 종료 | 결과 사전과 사유 → 같은 결과 사전. 해당 결과 객체만 변경 |
| `_unit_info` | 정규화 / 등록 단위 조회 | 단위 → 통화·배율·종류. 미등록이면 None |
| `_remove_affixes` | 문자열 정규화 / 바깥 통화·단위 분리 | 전체 문자열 → 숫자·단위·통화·오류. 숫자 중간 단위는 거부 |
| `_parse_decimal_token` | 문자열 정규화 / 전체 숫자형 검증 | 숫자 토큰·로케일 → Decimal 또는 None. 파일 접근 없음 |

각 함수의 정확한 인자·반환·예외·부작용은 구현 docstring에도 유지합니다. 새 기호 규칙을 추가할 때는 원본 근거와 충돌·경계 기대값을 함께 추가해야 합니다.
